# Как добавлять данные

Ни один из шагов не требует изменения кода приложения: всё хранится в SQLite и
редактируется через интерфейс или импорт CSV/JSON.

## 1. Бренд

**Каталог → Управление брендами → + Бренд**

| Поле | Обязательно | Комментарий |
|---|---|---|
| Название | да | отображается в каталоге и фильтрах |
| Slug | нет | генерируется автоматически (кириллица транслитерируется) |
| Страна, сайт, порядок сортировки | нет | служебные поля |

Удалить бренд можно только если к нему не привязаны устройства.

## 2. Устройство

**Каталог → + Устройство** (или `Ctrl+N`).

| Поле | Обязательно | Пример |
|---|---|---|
| Бренд | да | Samsung |
| Название модели | да | Galaxy A52 |
| **Точный код модели** | да | `SM-A525F` |
| Кодовое имя | нет | `a52q` (только если известно достоверно) |
| Аппаратная ревизия | нет | `rev1` |
| Процессор, платформа, ОЗУ, память | нет | внутренние технические данные |
| Версии ОС | нет | `Android 11, 12, 13` |
| Год выпуска | нет | 2021 |
| Источник | нет | ссылка на документацию/базу |
| Проверено | нет | ставьте только после сверки с источником |

Уникальность: `бренд + код модели + кодовое имя + ревизия` (без учёта регистра).

**Варианты устройства** (регион/CSC/загрузчик) добавляются в карточке устройства.
Они используются при проверке совместимости прошивок.

### Импорт устройств из CSV/JSON

**Импорт → Устройства (CSV/JSON)…** → «Скачать шаблон» → заполнить → «Проверить» →
«Импортировать».

Обязательные колонки: `Бренд`, `Название`, `Код модели` (или `brand`, `name`, `model_code`).
Разделитель `;` или `,`; кодировка UTF-8 (с BOM) или Windows-1251. Поддерживаются
заголовки на русском и английском. Отсутствующие бренды создаются, если включена
соответствующая опция.

JSON — массив объектов или `{"items": [...]}` с теми же именами полей.

## 3. Прошивка

**Firmware Center → + Запись** или **+ Прошивка** в карточке устройства.

Ключевые поля:

- **Имя файла** и **точный код модели** — обязательны;
- **Источник загрузки** (http/https) или локальный файл — обязательно хотя бы одно;
- версия ОС, номер сборки, регион, CSC, дата, размер, минимальный загрузчик;
- **эталонная SHA-256** — если известна, приложение сверит её с файлом;
- **статус проверки**: `Не проверено` / `Проверено сообществом` / `Проверено вручную` /
  `Недостоверно` (по умолчанию — «Не проверено»);
- инструкция и ограничения совместимости — свободный текст.

Порядок безопасной работы:

1. Создайте запись и укажите **точный** код модели и регион/CSC.
2. Нажмите **Проверить совместимость** — приложение сравнит код модели с устройством,
   регион/CSC с вариантами, проверит наличие загрузчика и контрольной суммы.
3. Нажмите **Прикрепить локальный файл…**, прочитайте предупреждение, введите
   `ПОДТВЕРЖДАЮ`, выберите файл. Файл будет проверен (расширение, целостность ZIP,
   SHA-256) и скопирован в локальную библиотеку прошивок.
4. При необходимости нажмите **Проверить контрольную сумму**.

Приложение **не** скачивает файлы из сети и **не** обходит защиту устройств.
Ссылка «Открыть страницу источника» открывается только после подтверждения.

### Импорт прошивок

Шаблон: `Импорт → Прошивки (CSV/JSON)…`. Прошивка привязывается только к **существующей**
модели с совпадающим кодом — совпадение названия телефона не учитывается.

## 4. Техническая библиотека

**Technical Library → + Материал** или **+ Материал** в карточке устройства.

- Категории: питание, зарядка, USB, RF, аудио, дисплей, камеры, датчики, память,
  процессор, общие материалы, ПО.
- Типы: PDF, схема, BoardView, фото платы, инструкция, заметка, ссылка, другое.
- Выбранный файл копируется в `<данные>/library/documents`.
- Заполняйте **права на использование** и **источник** — приложение не поставляет
  стороннюю документацию.
- Статус «Проверено вручную» автоматически ставит дату проверки.

**Заметки мастера** создаются в карточке устройства или в библиотеке и могут быть
привязаны к компоненту платы.

## 5. 3D-модель платы (пакет BoardView)

Подробный формат — [BOARDVIEW_FORMAT.md](BOARDVIEW_FORMAT.md).

Кратко:

1. Подготовьте JSON-пакет `smartphone-repair-os-board` v1 (или ZIP с JSON + фото).
2. **3D BoardView → Импорт платы** → выберите устройство → «Проверить файл» →
   «Импортировать».
3. Если плата уже существует, выберите её в списке «Заменить…» — компоненты будут
   перезаписаны, метки сохранятся отдельно.

Пакет можно экспортировать обратно (**Экспорт** в BoardView) — удобно для резервных
копий и правок в текстовом редакторе.

### Чего приложение не делает

Оно **не придумывает** геометрию, маркировки и назначение компонентов. Если в пакете
у компонента нет `position` и `size`, он не рисуется объёмным телом; он доступен в
списке и (при наличии `marker`) как метка на фото, а в интерфейсе отображается
предупреждение «нет геометрии».

Форматы `.brd`, `.bdv`, `.pcb` (BoardViewer/OpenBoardView) напрямую не читаются:
их нужно конвертировать в JSON-пакет. Скрипт-заготовка для конвертации — в
[BOARDVIEW_FORMAT.md, раздел «Конвертация»](BOARDVIEW_FORMAT.md#конвертация-внешних-форматов).

## 6. Массовое обновление каталога в будущем

Таблица `audit_log` хранит все изменения (сущность, действие, сводка, JSON-изменения).
Это база для подписанных обновлений каталога и синхронизации: планируется формат
пакета `{"format": "smartphone-repair-os-catalog", "signature": "..."}` с проверкой
подписи до применения. В MVP обновление выполняется импортом CSV/JSON.
