# Генерация: как из статистики YouTube получается ролик

Вкладка «Генерация» — мастерская, а не «кнопка вирусности». Она делает ровно три вещи,
каждую — отдельной кнопкой, чтобы было видно, где заканчивается статистика и начинается
фантазия модели.

```
ниша + формат (+ длительность)
   │
   ├─ 1. YouTube Data API: search.list → videos.list  →  разрез нишы (просмотры/час, медиана
   │      длительности, шаблоны заголовков, доля лайков)                [кэш 6 часов]
   │
   ├─ 2. Шесть тем, отранжированных по этому разрезу  →  балл по 5 осям
   │      (модель даёт формулировки, цифры даёт статистика)
   │
   ├─ 3. Скелет по битам (сумма таймингов == заказанная длительность, ни секунды врозь)
   │      → агент-монтажёр «Ножницы» вносит правки → балл обязан вырасти
   │      → проверка прав/монетизации → пакет: заголовок, описание, теги, SRT, превьюха
   │      → рецепт: manifest.json + render.sh (ffmpeg)
   │
   └─ «В очередь публикации» → вкладка «Задачи» → публикуешь руками
```

Код: `domain/engine/ViralLab.kt` (движок), `domain/agent/ViralEditor.kt` (агент),
`data/platform/YouTubeResearch.kt` (чтение YouTube), `data/repo/GenerationRepository.kt`
(оркестрация), `ui/generation/GenerationScreen.kt` (экран). Инварианты закреплены тестами
в `app/src/test/java/work/day/app/GenerationTest.kt` и `preview/lab.test.js`.

## Почему темы ранжирует не модель

`OfflineLlm`/LLM отвечает за **слова**: заголовок, хук, текст озвучки. Ранжирование и тайминги
считаются по разрезу нишы:

| Ось балла | Из чего считается |
|---|---|
| хук | длина и форма заголовка, наличие цифры, длина обещания, длительность хук-бита (длиннее 3 с в Shorts — минус) |
| ритм | доля самого длинного бита в ролике и число склеек на 10 секунд |
| раскрытие | как рано начинается «мясо» (цель ≤ 42 % ролика), есть ли бит доказательства, есть ли цифра в озвучке |
| удержание | петля в конце, конкретная причина вернуться вместо «подпишись», плотность текстовых плашек |
| монетизация | лицензия музыки, наличие субтитров, доля своего материала, дружелюбие нишы к рекламодателю |

Балл — не обещание охвата, а линейка: он показывает, **что в этом ролике ещё не сделано**.
Именно поэтому правки монтажёра проверяемы: каждая меняет вход, из которого `critique()`
считает ось, и `after.total >= before.total` закреплено тестом.

## Откуда цифры и что будет без ключа

`search.list` стоит **100 единиц квоты** за вызов (суточная квота проекта — 10 000), поэтому
исследование нишы кэшируется на 6 часов (`GenerationState.RESEARCH_TTL_MS`) и вызывается только
по кнопке «Подтянуть статистику» или при устаревшем кэше.

* Ключ YouTube API есть (`Настройки → ключ YouTube Data API`, либо токен Google из входа) —
  берётся топ по `order=viewCount` за 30 дней в указанном регионе, по 12 роликов на нишу.
* Ключа нет — движок считает по **демо-приорам нишы** и честно помечает это и в карточке темы
  («демо-приоры нишы (нет ключа YouTube API)»), и в строке состояния. Никаких выдуманных
  «1,2 млн просмотров» как факта.

## Проверка прав: почему пакет может не пройти

`ViralLab.compliance()` возвращает список проверок; блокирующие не дают положить ролик
в очередь публикации:

* музыка — только своё, CC0 или YouTube Audio Library (`NEEDS_PERMISSION`/`REPOSTED` = блокер);
* никаких чужих роликов целиком — переиспользованный контент не монетизируется;
* ≥ 60 % материала — своё (при < 34 % — блокер);
* субтитры обязательны (ролик смотрят без звука);
* в озвучке/описании нет призывов «скачать/перекачать чужое», нет накруток и покупной
  активности, нет демонетизирующих тем (азарт, кредиты, «сброс веса за…», 18+, оружие…);
* заголовок не обещает цифру, которой нет в ролике;
* реалистичный синтез голоса/видео помечен в описании (требование YouTube к синтетическому контенту);
* детская аудитория помечена явно (COPPA меняет и комментарии, и доход).

## Что делает `render.sh` и почему это не «генератор видео на телефоне»

Приложение не притворяется видеомонтажкой и не скачивает чужие ролики. Оно отдаёт **рецепт**:
`manifest.json` (биты, тайминги, плашки, роли), `captions.srt` (реальный SRT, а не «сделай субтитры»)
и bash-скрипт на ffmpeg, который склеивает **твои** куски из `clips/`, ложит лицензионную музыку,
делает кроп/пад под 9:16 или 16:9, нормализует громкость до −14 LUFS и прожигает плашки.
Запускается на компьютере: `bash render.sh`. Хватает и ручной сборки в CapCut — смысл рецепта в
таймингах и проверке, а не в конкретном инструменте.

## Границы

* Агент не публикует: кнопка кладёт пакет в общую очередь публикаций, слот — 18:30,
  дальше подтверждение руками в YouTube Studio / TikTok Studio.
* Никакой накрутки, масс-фолловинга, sub4sub, покупки просмотров, автоматических жалоб.
* Права на запись в канал не запрашиваются: Google — `youtube.readonly` +
  `yt-analytics.readonly`, TikTok — `user.info.basic` + `video.list`.
* «Ножницы» — не пятый агент смены: у него нет своего KPI и он не попадает в план дня,
  он работает только внутри конкретной сборки ролика. В очереди публикации его пакеты
  помечены агентом «Магнит», потому что идут в то же направление прироста.
