# Тестирование

Тесты не требуют подключённого телефона и **не выполняют запись на устройство**. Всё, что
касается внешних инструментов, проверяется через подставной `IProcessRunner` и временные каталоги.

## Запуск

```bash
dotnet test tests/NexusFirmware.UnitTests/NexusFirmware.UnitTests.csproj -c Release
dotnet test tests/NexusFirmware.IntegrationTests/NexusFirmware.IntegrationTests.csproj -c Release
```

Один тест:

```bash
dotnet test tests/NexusFirmware.UnitTests/NexusFirmware.UnitTests.csproj --filter "FullyQualifiedName~PathSafetyTests"
```

## Состав

### Юнит-тесты (`tests/NexusFirmware.UnitTests`)

| Файл | Что проверяет |
|------|---------------|
| `SafetyTests.cs` | нормализация путей в архивах (обход каталога, абсолютные пути, ADS, зарезервированные имена), SHA-256, маскирование серийных номеров и IMEI, валидация серийного номера/раздела/имени файла |
| `ArchiveFormatTests.cs` | определение формата по сигнатуре, безопасная распаковка ZIP, отказ при `../`, TAR-инспектор, лимиты, LZ4 frame (несжатый блок, литералы, повреждённый кадр), sparse-образы (RAW/FILL/DONT_CARE, unsparse), boot.img v0 |
| `ParserTests.cs` | payload.bin (protobuf-манифест), MediaTek scatter (платформа, разделы, проверка файлов), Qualcomm rawprogram XML, Samsung AP/HOME_CSC, ревизия загрузчика |
| `DeviceParsingTests.cs` | `adb devices -l` (device/unauthorized/offline), `getprop`, `fastboot devices`, `getvar all`, размеры разделов, JSON от `Get-PnpDevice`, классификация EDL/Download |
| `PlatformTests.cs` | политика доверия плагинам (хэш, издатель, подпись RSA, `canWriteDevice` без подписи), встроенный модуль, очередь заданий (успех, ошибка), формат отчётов |
| `FirmwareServiceTests.cs` | проверки совместимости (нет устройства, заблокированный загрузчик, чужая модель, непроверенная целостность, anti-rollback), сравнение прошивок, анализ и извлечение ZIP/GZIP, свободное место |

### Интеграционные тесты (`tests/NexusFirmware.IntegrationTests`)

| Файл | Что проверяет |
|------|---------------|
| `DatabaseTests.cs` | SQLite: сохранение и чтение прошивки, заметки, история импорта, поиск по хэшу, удаление, отчёты, снимки устройств, доверенные издатели |
| `FirmwareLibraryTests.cs` | импорт ZIP с расчётом хэша, дубликаты, проверка целостности после подмены файла, заметки, импорт каталога |
| `FlashingAndDiscoveryTests.cs` | планировщик: dry-run не запускает процессы, реальный план без разрешения блокируется, заблокированный загрузчик, честный отказ для Samsung, несколько образов из ZIP, лимиты распаковки, агрегация устройств от нескольких провайдеров |

## Что гарантируется тестами

* Опасные пути в архивах отклоняются до записи на диск.
* `DryRun` в планировщике не приводит к вызовам `adb`/`fastboot` (проверяется счётчиком запросов
  подставного раннера).
* Реальная запись невозможна без `AllowDeviceModification` и подтверждения.
* Заблокированный загрузчик, чужая модель, непроверенная целостность и откат версии блокируют план.
* Плагин с несовпадающим хэшем, неизвестным издателем, неверной подписью или без
  `AllowPluginLoading` не загружается.
* Повреждённые файлы (LZ4, sparse, payload) дают понятную ошибку, а не «успех».

## Чего тесты не делают

* Не подключаются к реальным устройствам и не проверяют прошивание «в железе» — для этого нужен
  стенд и отдельный регламент.
* Не проверяют подлинность реальных прошивок производителей (нет доверенных ключей/хэшей).
* Не эмулируют закрытые протоколы (Odin, BROM, Firehose) — их в приложении нет.

## CI

GitHub Actions (`.github/workflows/ci.yml`) запускает оба набора на каждый push и pull request:

* `tests` — Ubuntu: restore, сборка библиотек и тестов, `dotnet test`;
* `windows` — Windows: сборка всего решения (включая WPF), публикация self-contained EXE,
  сборка установщика Inno Setup, выгрузка артефактов;
* `release` — по тегу `v*` или вручную: релиз с установщиком и портативным EXE.

Результаты тестов выгружаются артефактом `test-results` (TRX).
