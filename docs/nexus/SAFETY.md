# Модель безопасности

NEXUS Firmware Studio работает с устройством, на котором могут быть важные данные. Поэтому
безопасность — не «дополнительная функция», а ограничение, встроенное в архитектуру: опасное
действие невозможно выполнить случайно или «по умолчанию».

## 1. Ничего не пишется автоматически

* `FlashOptions.DryRun = true` — значение по умолчанию. В этом режиме выполняются только
  проверки и построение плана; к устройству не отправляется ни одна команда записи.
* Реальная запись требует одновременного выполнения трёх условий:
  1. `DryRun = false` (пользователь явно снял галочку);
  2. `AllowDeviceModification = true` (отдельная галочка «Разрешить изменение устройства»);
  3. подтверждение вводом серийного номера в диалоге (`ConfirmSerialWindow`).
* Перед подтверждением устройство перепроверяется: если оно отключилось или сменило режим,
  задание прерывается до первой команды записи.
* `ReadOnlyMode` в настройках (по умолчанию включён) дополнительно запрещает любые операции,
  изменяющие устройство.

## 2. Планы с блокирующими проверками не выполняются

`OperationPlan` содержит `CompatibilityItem` с уровнями `Info`, `Warning`, `Blocking`.
Если есть хотя бы одна блокирующая проверка, кнопка выполнения недоступна, а сервис
`FlashPlanner` отказывается создавать задание. Блокирующими считаются, в частности:

* устройство не выбрано или не в поддерживаемом режиме;
* загрузчик заблокирован или состояние неизвестно (для операций записи);
* модель/производитель прошивки не совпадает с устройством;
* хэш файла не совпадает с сохранённым;
* ревизия загрузчика прошивки ниже установленной (anti-rollback) — если обе ревизии известны;
* архив не прошёл проверку безопасности (path traversal, слишком большие размеры);
* стратегия для данного протокола не реализована.

## 3. Разрушительные операции отделены

`OperationRisk`:

| Уровень | Примеры | Требования |
|---------|---------|-----------|
| `ReadOnly` | `getprop`, `getvar`, анализ файла | нет |
| `ModifiesDevice` | `fastboot flash`, `adb reboot` | подтверждение + разрешение изменения |
| `Destructive` | `fastboot -w`, erase раздела | дополнительно `ConfirmDataWipe` и предупреждение о потере данных |

Шаг с `Destructive` не может появиться в плане, если пользователь не включил соответствующую
опцию: планировщик не добавляет его молча.

## 4. Работа с файлами

* Анализ **никогда** не изменяет исходный файл: все операции чтения, распаковка — во временный
  каталог (`PathSafety.CreateWorkDirectory`) или в каталог, выбранный пользователем.
* Каждый путь внутри архива нормализуется (`PathSafety.TryNormalizeArchiveEntry`), отклоняются:
  `..`, абсолютные пути, диски (`C:`), UNC, альтернативные потоки NTFS (`file:stream`),
  зарезервированные имена (`CON`, `NUL`, …), пустые имена.
* Лимиты распаковки (`ExtractionLimits`): общий объём, размер записи, количество записей,
  коэффициент сжатия — защита от zip-бомб.
* Свободное место проверяется перед извлечением больших архивов.
* SHA-256 считается потоково; хэш хранится в базе и сверяется при повторной проверке.

## 5. Командная строка

Все внешние вызовы идут через `IProcessRunner` с `ArgumentList` (без склейки строки), поэтому
пользовательские значения не могут добавить лишний аргумент. Значения дополнительно
валидируются:

* серийный номер — `^[A-Za-z0-9._-]{1,128}$`;
* имя раздела — `^[a-z0-9_]{1,64}$`;
* ключ свойства — `^[A-Za-z0-9._:-]{1,256}$`;
* путь — существующий файл разумного размера.

Произвольные shell-команды не принимаются: в разделах ADB/Fastboot доступны только белые
списки диагностических команд.

## 6. Персональные данные

* Серийные номера и IMEI маскируются: `R58M12345` → `R58•••••345`, IMEI — `••••••••••`.
* `Redactor.MaskText` вычищает идентификаторы из строк журнала; `MaskSerialsInLogs`
  включён по умолчанию.
* Приложение не собирает и не отправляет данные: нет телеметрии, нет «облачных» проверок.
  Единственный сетевой запрос — проверка обновлений по явной команде пользователя, и он
  передаёт только текущую версию приложения.

## 7. Плагины

Загрузка внешнего кода выключена по умолчанию. Включение требует:

1. явного флага `AllowPluginLoading` в настройках;
2. корректного `manifest.json` (id, версия, сборка, точка входа);
3. совпадения SHA-256 сборки с манифестом;
4. издателя в списке доверенных (`trusted_publisher` в SQLite, добавляется вручную).

Любое несоответствие → сборка не загружается, причина показывается в разделе «Плагины».
Плагин не может расширить права приложения: он работает в его процессе, поэтому доверие
выдаётся осознанно.

## 8. Драйверы

* Проверка подписи установщика выполняется через `Get-AuthenticodeSignature`; результат
  показывается как есть (подписан/не подписан, издатель, отпечаток, метка времени).
* Приложение **не** отключает проверку подписи драйверов, не меняет политику Windows и не
  устанавливает драйверы молча: только инвентаризация, ссылки на официальные источники и
  инструкции.

## 9. Что приложение принципиально не делает

* Не обходит блокировку загрузчика, подпись образов, Secure Boot, SLA/DAA MediaTek,
  FRP/блокировку аккаунта, DRM.
* Не подделывает результаты: если данные недоступны — показывается «недоступно», если операция
  не поддерживается — план помечается блокирующей проверкой с объяснением.
* Не работает с закрытыми протоколами иначе как через официальные SDK/инструменты,
  установленные пользователем.
* Не изменяет оригинальные файлы прошивок.
* Не запускает код плагинов без проверки подписи и доверия.

## 10. Проверка соблюдения

Правила закреплены тестами (`tests/NexusFirmware.UnitTests`):

* `PathSafetyTests` — обход каталога, абсолютные пути, ADS, зарезервированные имена;
* `RedactorTests` — маскирование серийных номеров и IMEI;
* `InputValidatorTests` — валидация серийного номера, раздела, имени файла;
* `CompatibilityTests` — блокировка при заблокированном загрузчике, несовпадении модели,
  неподтверждённой целостности, откате версии;
* `FlashPlannerTests` — dry-run не запускает процессы, реальный план без разрешения блокируется;
* `PluginTrustTests` — несовпадение хэша, неизвестный издатель, выключенная загрузка;
* `Lz4FrameTests` / `ZipInspectorTests` — повреждённые и опасные архивы отклоняются.
