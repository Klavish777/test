# План развития

Порядок отражает приоритет: сначала то, что делает приложение полезнее без риска, затем —
расширение поддерживаемых сценариев, и только в конце — то, что требует закрытых протоколов.

## Этап 1 — стабильность и данные (следующий)

* [ ] Миграции схемы SQLite с версионированием (`schema_version` уже есть, нужны шаги 1→N).
* [ ] Полнотекстовый поиск по каталогу прошивок и заметкам.
* [ ] Проверка свободного места и хэшей перед длительными операциями в фоновом режиме.
* [ ] Экспорт каталога прошивок в CSV/JSON и импорт из него.
* [ ] Автоматические тесты планировщика на матрице «режим × загрузчик × тип пакета».

## Этап 2 — работа с образами

* [ ] Распаковка `payload.bin` по операциям (REPLACE/REPLACE_BZ/REPLACE_XZ/ZERO/NEW).
* [ ] Сборка sparse-образов из raw (обратная операция к текущему `UnsparseAsync`).
* [ ] Разбор `super.img` (dynamic partitions) и списка логических разделов.
* [ ] Проверка подписи AVB (`vbmeta`) — только чтение и отображение, без обхода.
* [ ] Сравнение образов по секциям, а не только по файлам.

## Этап 3 — устройства и драйверы

* [ ] История подключавшихся устройств с маскированием идентификаторов.
* [ ] Диагностика USB-дерева (хаб/порт/скорость) для нестабильных подключений.
* [ ] Проверка подписи уже установленных драйверов (не только установщиков).
* [ ] Наборы официальных драйверов с проверкой источника (без автоматической установки).

## Этап 4 — расширяемость

* [ ] Публичный API плагинов с версионированием контракта.
* [ ] Каталог плагинов с подписью издателя и проверкой отзыва.
* [ ] Изолированное исполнение плагинов (отдельный процесс с ограничением прав).
* [ ] Мастер создания модуля производителя внутри приложения.

## Этап 5 — протоколы производителей (только легальные пути)

Реализация возможна **только** через официальные SDK, документацию или публичные спецификации,
и только для операций, которые не обходят защиту:

* [ ] Fastboot-расширения, документированные производителем (например, служебные переменные).
* [ ] MediaTek: работа с официальным DA, если производитель предоставляет его для сервисных
  центров и это разрешено лицензией.
* [ ] Samsung: сценарии, разрешённые официальным инструментом (без обхода подписи и счётчиков).
* [ ] Qualcomm: Firehose только с официальной программой и подписанными образами.

Пункты этого этапа не будут реализованы, если требуют обхода Secure Boot, SLA/DAA, блокировки
загрузчика, FRP или DRM.

## Явно вне плана

* Обход любых защит и блокировок.
* Извлечение персональных данных, переписки, ключей.
* Скрытая телеметрия или передача данных третьим лицам.
* Автоматическая установка драйверов и отключение проверки подписей.
