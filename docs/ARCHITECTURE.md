# Архитектура

## Слои

```
┌───────────────────────────────────────────────────────────────┐
│ ui/            PySide6: окно, страницы, диалоги, тема         │
│                (никакой SQL — только AppContext и репозитории)│
├───────────────────────────────────────────────────────────────┤
│ services/      поиск, импорт/экспорт, пакеты плат, прошивки,  │
│                резервные копии, сидирование демо-данных       │
├───────────────────────────────────────────────────────────────┤
│ boardview/     scene.py (камера/геометрия, без Qt)            │
│                viewer_3d.py, photo_view.py (виджеты)          │
├───────────────────────────────────────────────────────────────┤
│ data/          database.py, миграции, модели, репозитории     │
├───────────────────────────────────────────────────────────────┤
│ core/          пути, ошибки, логирование, i18n, безопасность, │
│                секреты, лицензирование                        │
└───────────────────────────────────────────────────────────────┘
```

Правила:

1. `core` не импортирует Qt и SQL — используется и в тестах, и в консольных режимах.
2. `data` не импортирует Qt.
3. `ui` не выполняет SQL напрямую: только `AppContext` → репозитории/сервисы.
4. Любая ошибка домена — исключение из `core/errors.py` с понятным пользователю текстом.

## Точка сборки приложения

`repair_os/services/context.py` (`AppContext`) создаёт каталоги, открывает базу,
применяет миграции, поднимает репозитории и сервисы, при первом запуске загружает
демо-данные. Это единственная точка, где всё связывается вместе.

## Схема базы данных (SQLite, схема v2)

| Таблица | Назначение | Ключевые индексы |
|---|---|---|
| `brands` | производители | `slug` (unique) |
| `devices` | модели, внутренние техданные | unique `(brand, model_code, codename, revision)`, индексы по имени/коду/кодовому имени |
| `device_variants` | регионы, CSC, загрузчик | `device_id`, `model_code` |
| `firmware` | записи прошивок | `device_id`, `model_code`, `build_number`, `file_name`, `region` |
| `firmware_sources` | источники (отдельно от записей) | `name` (unique) |
| `board_models` | платы, размеры, пакет | `device_id`, `board_code`, `package_checksum` |
| `board_components` | компоненты платы | unique `(board_model_id, designator)`, `layer` |
| `board_annotations` | пользовательские метки | `board_model_id` |
| `technical_documents` | материалы библиотеки | `device_id`, `category`, `title` |
| `component_references` | справки по компонентам | `designator`, `marking` |
| `repair_notes` | заметки мастера | `device_id` |
| `favorites` | избранные устройства | `device_id` (unique) |
| `recent_devices` | история открытий | `device_id` (PK), `opened_at` |
| `app_settings` | настройки ключ-значение | PK `key` |
| `audit_log` | журнал изменений | `(entity, entity_id, created_at)` |

Связи — через `FOREIGN KEY` с `ON DELETE CASCADE/SET NULL`, `PRAGMA foreign_keys = ON`.
Проверки значений заданы `CHECK`-ограничениями (`side`, `verification_status`, `doc_type`).

### Миграции

Файлы `<номер>_<имя>.sql` в `repair_os/data/migrations`. При старте:

1. создаётся таблица `schema_migrations`;
2. применяются только новые миграции, каждая — в отдельной транзакции;
3. сохраняется SHA-256 файла миграции: ручные правки уже применённой миграции
   обнаруживаются по несовпадению контрольной суммы;
4. перед восстановлением база проверяется `PRAGMA integrity_check`.

Добавление миграции: создайте `003_my_change.sql`, приложение применит её при
следующем запуске. **Никогда** не правьте уже выпущенные миграции.

## 3D BoardView

`boardview/scene.py` — чистый Python: векторы, камера (yaw/pitch/distance/target),
перспективная проекция, грани параллелепипедов, освещённость по нормалям.

`viewer_3d.py` — `QWidget` с `paintEvent`: собирает грани, сортирует по глубине
(painter's algorithm), рисует `QPainter`-ом, выполняет picking по спроецированным
прямоугольникам и подсветку выбранного компонента.

Почему не Qt Quick 3D/WebEngine:

* нет требования к GPU и драйверам — работает в RDP, виртуалках и на слабых ПК;
* одна и та же картинка на Windows и Linux, предсказуемые тесты;
* полный контроль над выбором компонентов и слоями;
* проще распространение: без WebEngine сборка легче и не требует QtWebEngine.

Ограничение: нет сложных шейдеров и моделей высокой полигональности. Для плат
(корпуса-параллелепипеды) этого достаточно; при необходимости `SceneData` можно
заменить на Qt Quick 3D без изменения базы и сервисов.

## Безопасность

* Все строки валидируются в `data/models.py` (длины, формат кода модели, даты, enum).
* Файлы импортируются через `core/security.py`: проверка расширения, размера,
  кодировки, безопасная распаковка ZIP (path traversal, симлинки, zip-бомбы).
* Контрольные суммы SHA-256 сверяются вручную и при прикреплении файла.
* Опасные операции требуют ввода слова подтверждения (`DangerDialog`).
* Токены внешних сервисов хранятся только в зашифрованном виде (`secrets_store.py`,
  Fernet); без `cryptography` — только в памяти процесса.
* Никаких сетевых запросов приложение не выполняет; ссылки открываются в браузере
  после подтверждения.

## Расширяемость и монетизация

`core/entitlements.py`: `Feature`, `Edition`, `Entitlements`, интерфейс
`EntitlementProvider`. В MVP `LocalEntitlementProvider` возвращает все права, оплата
не требуется. Добавление подписки — новая реализация провайдера + `set_provider()`,
без изменений в UI (страницы уже проверяют права через `feature_available`).

Запланированные точки расширения:

| Возможность | Точка расширения |
|---|---|
| Платные 3D-модели | поле `board_models.license_note` + entitlements `BOARDVIEW_3D` |
| Расширенная библиотека | `technical_documents.verification_status` + entitlements `PREMIUM_CONTENT` |
| Синхронизация | `audit_log` как журнал изменений + новый сервис синхронизации |
| Аккаунт | `EntitlementProvider`/`SecretStore`, отдельный сервис авторизации |
| Подписанные обновления каталога | формат пакета каталога + проверка подписи перед импортом |

## Тестируемость

Бизнес-логика не зависит от Qt: тесты БД, репозиториев и сервисов работают без экрана.
UI-тесты используют `QT_QPA_PLATFORM=offscreen` и проверяют навигацию, выбор
компонентов, фильтры и валидацию диалогов.
