# Work Day

**Свежий debug-APK:** [WorkDay-debug.apk](https://github.com/Klavish777/test/releases/download/workday-latest/WorkDay-debug.apk)
 · [страница релиза](https://github.com/Klavish777/test/releases/tag/workday-latest) (пересобирается CI при каждом пуше в `android/`)

**Android-приложение с четырьмя AI-агентами, которые ведут рабочий день твоего канала на YouTube и TikTok.**
Не «кнопка накрутки», а смена: у каждого агента своё направление, свои KPI, свои плейбуки и вечерний отчёт.

| Агент | Направление | Что делает в смене | Главная метрика |
|---|---|---|---|
| 🧲 **Магнит** | Прирост аудитории | переупаковка заголовков и обложек под поиск, аудит воронки подписки, серии с продолжением, вход в тренд за 24–48 ч, кластеры ключей | чистый прирост подписчиков/нед · CTR обложек · подписчики на 1000 просмотров |
| 🛰️ **Разведчик** | Привлечение аудитории | нарезка длинного видео на 4 вертикальных отрывка с таймкодами, адаптация текстов под вторую площадку, питчи на коллаборации, присутствие в чужих комментариях, посевы, локализация | охват · доля новой аудитории · переходы Shorts → длинное |
| ⚡ **Ускоритель** | Ускорение роста | 2 гипотезы-эксперимента в неделю, «формула победителя» из топ-5 роликов, ритм публикаций и буфер, репаковка старого каталога, карта удержания, план платного разгона с юнит-экономикой | скорость роста (нед/нед) · удержание · стабильность публикаций |
| ✨ **Искра** | Стимулировать активность | черновики ответов на комментарии в твоём тоне, карта CTA по таймкодам, опросы и челленджи, маховик UGC, рундаун live-эфира, мягкая модерация | ER · комментариев на ролик · ответы ≤ 1 часа · сохранения |

Итого: **10 плейбуков и 24 действия агентов** (`TaskKind` в домене и `ACTIONS` в прототипе — один и тот же словарь).

## Чего в приложении нет — и не будет

Work Day **не накручивает** аудиторию и не публикует сам. Ни ботов, ни покупных просмотров/подписчиков/лайков,
ни масс-фолловинга, ни sub4sub, ни автоматических жалоб, ни постинга от имени автора.
Это не перестраховка: за искусственную активность YouTube и TikTok банят канал, а вместе с накруткой
улетают и органические охваты — то есть то, ради чего всё затевалось.

Права на запись в аккаунт у приложения нет вообще, поэтому «случайно» нарушить правила нельзя даже
при уровне автономии «Планировщик»: агент готовит материал, ставит его в очередь публикации, напоминает
в слот — а кнопку «Опубликовать» нажимаешь ты. Границы зафиксированы в коде (`domain/SafetyPolicy.kt`)
и в системном промпте каждого агента, и проверяются тестами.

## Как устроена смена

```
09:00  старт смены → каждый включённый агент строит план: (2 + интенсивность) задач на день
       планирование распределяет задачи по слотам 09:00–18:00 (тяжёлые — в первую половину дня)
  ↓    цикл: агент берёт задачу по слоту → дергает модель (или офлайн-движок) → выдаёт материал
       риск LOW    → задача закрывается сразу
       риск MED/HIGH → статус «Ждёт одобрения» → ты одобряешь → пакет уходит в очередь публикации
18:00  отчёт: что закрыто, что зависло, оценка каждого агента, план на завтра
```

Задачи не «выполняются всегда все»: агент физически берёт только то, что упёрлось в текущий слот смены,
а выключенный агент или выключенный плейбук просто не попадает в план.

## Модель и ключи

* **Своего сервера нет.** Приложение обращается напрямую к OpenAI-совместимому API (OpenAI, OpenRouter,
  Together, LM Studio, Ollama, vLLM) — адрес, ключ и модель задаёшь в «Настройках». Ключ живёт только
  на устройстве (DataStore), никуда не проксируется.
* **Без ключа приложение не пустое**: работает офлайн-движок (`data/llm/OfflineLlm.kt`) — по шаблону
  каждого из 24 действий собирает черновик материала из контекста канала. Его тексты помечены
  `источник: офлайн-движок`, чтобы не путать с генерацией модели.
* **Статистика**: `data/platform/YouTubeDataApi.kt` читает публичные цифры канала через
  YouTube Data API v3 (ключ с правами только на чтение); TikTok-цифры вставляются CSV из
  TikTok Studio (`data/platform/AnalyticsImporter.kt`). Пока импорт не сделан, график живёт на
  детерминированных демо-данных и честно это подписывает.

## Сборка в один клик

`.github/workflows/workday-apk.yml` на GitHub Actions: JDK 17 → Android SDK 35 → Gradle 8.11.1 →
`:app:testDebugUnitTest` → `:app:assembleDebug` → APK в релиз `workday-latest` (постоянная ссылка на загрузку)
и артефактом. При ошибке компиляции workflow коммитит `ci-build.log` с текстом ошибок в ветку — его видно
в истории, не залезая в логи Actions.

## Структура репозитория

```
android/                          Android-приложение (Kotlin 2.0.21, Jetpack Compose, Material 3)
  app/src/main/java/work/day/app/
    MainActivity.kt, WorkDayApp.kt
    core/PersistedStore.kt         один JSON-файл вместо БД: чтение синхронно, запись асинхронно
    di/AppContainer.kt             ручной DI: хранилища, клиенты LLM, движок смены
    domain/model/                  Enums.kt (Platform, TaskStatus, Risk, 24 TaskKind), AgentId.kt,
                                   Domain.kt (ChannelProfile, AgentTask, Artifact…), Playbook.kt
    domain/agent/                  GrowthAgent.kt (контракт + промпт-конвейер), Agents.kt (4 персоны)
    domain/engine/ShiftEngine.kt   смена: фазы, тики, очередь, одобрения, отчёт
    domain/SafetyPolicy.kt         жёсткие границы: что агенты не делают никогда
    data/llm/                      LlmClient, OpenAiCompatLlm, OfflineLlm
    data/repo/                     SettingsRepository (DataStore), WorkspaceRepository, SampleMetrics
    data/platform/                 YouTubeDataApi (чтение), AnalyticsImporter (CSV)
    ui/                            WorkDayRoot + WorkDayViewModel и 5 вкладок:
                                   Смена · Агенты · Задачи · Рост · Настройки
  app/src/test/…/DomainTest.kt     юнит-тесты домена и парсера (./gradlew :app:testDebugUnitTest)

preview/                          кликабельный прототип интерфейса (тот же движок, чистый JS)
  index.html app.js engine.test.js package.json
docs/ARCHITECTURE.md              слои, поток данных, почему так, а не иначе
docs/AGENTS.md                    спецификация 4 агентов, плейбуков и риск-модели
docs/BUILD.md                     как собрать APK и что понадобится
```

## Запуск

```bash
# прототип интерфейса + тесты движка (Node 18+, сервер не нужен — можно открыть файл)
cd preview && node --test engine.test.js        # 9 тестов: модель, план смены, риск-модель, экраны
python3 -m http.server 8137 --bind 0.0.0.0      # и открыть http://localhost:8137

# Android-приложение — открыть android/ в Android Studio, Gradle Sync, Run.
# Или из консоли (нужны JDK 17 + Android SDK):
cd android && ./gradlew :app:assembleDebug :app:testDebugUnitTest
```

## Статус кода

Собирается и проходит тесты в CI (Kotlin 2.0.21, Compose BOM 2024.10.01, `:app:testDebugUnitTest` +
`:app:assembleDebug` зелёные). Локально в песочнице сборку не проверить — там нет JDK и Android SDK,
поэтому CI и есть способ получить бинарник. Если собираешь сам, список мест, которые обычно правят после
импорта проекта в Android Studio, — в `docs/BUILD.md`.
